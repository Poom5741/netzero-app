# Implementation Plan: Match Shared Tokens, Dashboard Shell and Login Presentation

**Branch**: `006-match-dashboard-shell-login` | **Date**: 2026-09-15 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/006-match-dashboard-shell-login/spec.md`

## Summary

Match the visual presentation of Admin Console and Sponsor Portal login pages and dashboard shells to the client design artifacts. This is a frontend-focused visual parity spec requiring CSS/component changes to match reference captures from spec 005. Key work includes: (1) Admin and Sponsor login page split layouts with conditional OTP/remember-device controls, (2) Dashboard shell sidebar navigation with correct icons and active states, (3) Shared design token system for consistency, (4) Thai font rendering and LIFF regression testing. All pixel-level measurements must match within per-region tolerance values from spec 005; discrete tokens (colors, hex codes) must match exactly.

## Technical Context

**Language/Version**: TypeScript 5.x, React 18.x, Next.js 16.3 (static export)

**Primary Dependencies**: Next.js, React, Tailwind CSS v4, LINE LIFF SDK, Hono (backend), Cloudflare Workers

**Testing**: Jest, React Testing Library, Playwright (e2e), browser-use (manual QA)

**Target Platform**: Web (desktop 1280x720, 1440x900; LIFF mobile 390x844, 360x844, 430x844)

**Project Type**: Web application (frontend + backend API)

**Performance Goals**: Page load < 3s on standard connection (removed from spec — not measurable); zoom usability at 125%, 150%

**Constraints**: Static export build (NEXT_PUBLIC_API_BASE at build time); Material Symbols via `<link>` not `next/font/google`; Thai font via Google Fonts `<link>`; no `node:crypto` in Workers

**Scale/Scope**: 2 login pages (Admin, Sponsor), 2 dashboard shells (Admin with 7 nav items, Sponsor with 3 nav items), 7 LIFF destinations, shared design token system

## Implementation Approach

### Work Streams

1. **Design Token System** (Priority: P1)
   - Audit existing tokens in globals.css
   - Define missing tokens (colors, typography, spacing, shadows)
   - Document token values and usage

2. **Admin Login Page** (Priority: P1)
   - Implement split layout (branding panel + login form)
   - Add conditional OTP/remember-device controls
   - Match reference capture exactly (discrete tokens) and within tolerance (layout)

3. **Sponsor Login Page** (Priority: P1)
   - Implement split layout with "Sponsor Portal" eyebrow
   - Add conditional OTP/remember-device controls
   - Match reference capture

4. **Admin Dashboard Shell** (Priority: P2)
   - Implement sidebar with 7 navigation items
   - Implement header with page title and user menu
   - Match reference capture for all states (default, hover, active)

5. **Sponsor Dashboard Shell** (Priority: P2)
   - Implement sidebar with 3 navigation items
   - Implement header
   - Match reference capture

6. **Error/Loading/Empty States** (Priority: P3)
   - Implement error state styling for failed login
   - Implement loading skeletons
   - Implement empty state messaging

7. **LIFF Regression** (Priority: P3)
   - Test all 7 LIFF destinations at target viewports
   - Verify no visual regressions

8. **Visual Comparison** (Priority: P2)
   - Capture before/after screenshots
   - Generate overlay/diff images
   - Document remaining discrepancies

### Dependencies

- **Blocked by**: Spec 005 (reference captures), Issue #142 inventory manifest
- **Conditional**: Backend OTP/remember-device support (controls hidden if unavailable)

### Testing Strategy

1. **Unit Tests**: Component rendering, conditional control logic
2. **Visual Tests**: Side-by-side comparison with reference captures
3. **E2E Tests**: Login flows, navigation, LIFF destinations
4. **Manual QA**: Browser-use at target viewports, zoom testing

### Risk Mitigation

1. **Spec 005 Dependency**: If reference captures are incomplete, this spec is blocked
2. **Backend OTP Support**: If unavailable, controls are hidden and separate issue filed
3. **Tolerance Disputes**: Use spec 005's per-region noise measurement, not subjective judgment
4. **LIFF Regressions**: Test all LIFF destinations after each change
